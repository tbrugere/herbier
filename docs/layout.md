# Herbier — Repository layout

Status: proposal, 2026-09-16. Refines `architecture.md` §9. Differences
from that sketch, all deliberate: a pure `domain/` library is added (native
tests); `reference/` and `resolver/` merge into `refs/` (same HTTP sources);
`map/` becomes `geo/` (it also holds tiles and geocoding); `capacitor/`
becomes `bindings/` (MapLibre, pmtiles and exifr bindings live there too);
`test/`, `scripts/` and `.github/` are new. The mockup
(`design_handoff_herbier/`) stays the source of truth for screens and tokens.

## 1. Top level

```
herbier/
  dune-project            one project, one package `herbier`
  herbier.opam            generated by dune from dune-project (do not edit)
  dune.lock/              `dune pkg lock` output, committed (see decision 2)
  .ocamlformat            pinned version, profile = default
  package.json            Capacitor CLI + plugins, maplibre-gl, pmtiles, exifr, esbuild
  package-lock.json
  capacitor.config.ts     appId, webDir → _build/default/web/dist
  app/                    all OCaml; one dune library per subdir + main.ml (§2)
  web/                    static shell sources: index.html, css/, fonts/, js/, map/ (§3)
  android/                Capacitor Android project, generated then committed (§4)
  supabase/               config.toml, schemas/, migrations/, tests/ (§5)
  test/                   OCaml tests, native and jsoo (§6)
  scripts/                dev loop, icon subset, PMTiles extract, release
  docs/                   stack, architecture, this file, handoff, research, notes
  .github/workflows/      ci.yml, android.yml (§7)
```

Dune units: every `app/<dir>/` is a **library** named `herbier_<dir>`;
`app/main.ml` is the only **executable** (`(modes js)`); `web/dune` holds
copy/concat **rules** under alias `@web`; `test/*/dune` are **tests**.
Nothing outside `app/`, `web/`, `test/` has a `dune` file.

## 2. `app/` — OCaml

```
app/
  dune                    executable main, (modes js), js_of_ocaml flags
  main.ml                 entry: init plugins, open db, mount router, start sync
  domain/                 pure types and rules; Stdlib + yojson + ptime + uuidm, no Brr
    plant.ml  observation.ml  photo.ml  tag.ml  reference.ml   records + codecs
    ids.ml                UUID generation, typed ids
    merge.ml              last-write-wins on updated_at, outbox-wins rule
    link.ml               URL/text → classified link (gbif key, plantnet name, …), pure
    projection.ml         reference rows → ReferenceSnapshot fields (4f), pure over JSON
    places.ml             500 m clustering, Haversine, day-place choice (4c)
    version.ml            generated by a dune rule from `git describe` (User-Agent)
  bindings/               Jv/Brr bindings only; no domain, no logic
    cap_sqlite.ml  cap_filesystem.ml  cap_app.ml  cap_share_target.ml
    cap_social_login.ml  cap_uploader.ml  cap_geolocation.ml  cap_camera.ml
    cap_preferences.ml  maplibre.ml  pmtiles.ml  exifr.ml
  store/                  local SQLite (§3 of architecture)
    db.ml                 open, exec, typed row helpers over cap_sqlite
    schema.ml             ordered migrations as SQL strings, `user_version`
    plants.ml  observations.ml  photos.ml  tags.ml  references.ml   queries per table
    outbox.ml  sync_state.ml  settings.ml  search.ml (FTS5)
    files.ml              previews/, refthumbs/, tiles/ paths under Directory.Data
  sync/                   Supabase (§4 of architecture)
    auth.ml               Google id token → signInWithIdToken, session, auto-refresh
    postgrest.ml          upsert / select-since, JWT, paused-project detection
    push.ml  pull.ml  engine.ml (schedule, backoff)  previews_mirror.ml
  photos/                 §5 of architecture
    exif.ml  preview.ml (canvas resize+encode)  capture.ml (getUserMedia / pick)
    drive.ml (files.create, folders, trashed check)  upload_queue.ml  health.ml
  refs/                   §6–7 of architecture
    http.ml               fetch with User-Agent + rate-limited queue
    sources/              gbif.ml  wikidata.ml  wikipedia.ml  tela.ml  inpn.ml
    pipeline.ml           fan-out per gbif_key, one reference row per source
    resolver.ml           Domain.Link + network lookups → gbif_key + partial snapshot
    regional.ml           pluggable France layer (Tela, INPN), on/off by setting
  geo/                    §8 of architecture
    map.ml                OCaml face of the MapLibre facade (create, set_data, fly_to, …)
    style.ml              online (OpenFreeMap) / offline (pmtiles://) style switch
    tiles.ml              region extract download and storage
    geocode.ml            Photon / Géoplateforme forward and reverse
  ui/
    rb.ml                 react ↔ Brr glue (API in notes/ocaml-react-primer.md §6)
    tokens.ml             design tokens; source for web/css/tokens.css (§3)
    state.ml              global signals: filters, network, account (handoff « État »)
    router.ml             route type, `S.bind` over the current screen, release on switch
    app.ml                wires services: after-save → outbox push + reference fetch, …
    widgets/              chip, card, list_row, tab_bar, sheet, dialog, text_field,
                          month_grid, photo_grid, icon, viewer_zoom (imperative)
    screens/              one file per mockup screen, handoff id in a header comment
      collection.ml (4a)  map_tab.ml (4b)  journal.ml (4c)  record.ml (4d)
      saved.ml (4e)       species.ml (4f, 4g)  observation.ml (4h)
      resolve.ml (4i, 4j, 4k, 5c: one screen, four entry modes)
      tags.ml (4l, 5d)    settings.ml (4m)  onboarding.ml (4n)
      edit_plant.ml (5a)  move_point.ml (5b)  viewer.ml (5e)
```

Dependency direction (enforced by each `dune` file's `libraries` field):

```
domain    ← nothing
bindings  ← brr
store     ← domain, bindings
sync | photos | refs | geo   ← domain, store, bindings   (siblings never import each other)
ui        ← everything above + react, reactiveData
main      ← ui
```

Notes:

- Anything testable without a browser goes in `domain/`, even if one
  service uses it (`link.ml`, `projection.ml`, `places.ml`); `domain/` uses
  `yojson`, never `Jv`, so it builds natively and under jsoo.
- Cross-service orchestration (save ⇒ outbox push ⇒ reference fetch ⇒
  geocode) lives in `ui/app.ml`, which keeps the siblings independent.
- `ui/` uses `(include_subdirs qualified)`: `Screens.Collection`,
  `Widgets.Chip`. `map_tab.ml` avoids shadowing `Stdlib.Map` in `Screens`.
- The map, camera `<video>` and pinch viewer are ordinary widgets holding a
  JS object and subscribing to signals; no "islands" directory.

## 3. `web/` — static shell and build output

```
web/
  dune                    @web alias: copy index.html, concat css, bundle js, copy fonts,
                          copy ../app/main.bc.js → dist/app.js
  index.html              loads dist/vendor.js then dist/app.js
  css/
    tokens.css            generated from ui/tokens.ml (see decision 4); custom properties
    base.css              reset, @font-face, type scale, sun-readability rules (5f)
    widgets.css           chips, cards, tab bar, sheets, dialogs, fields
    screens.css           per-screen layout, one commented block per handoff id
  fonts/                  Manrope, Newsreader (variable woff2), Material Symbols subset
  js/
    vendor.js             esbuild entry: imports Capacitor plugins, maplibre-gl, pmtiles,
                          exifr; exposes them on globalThis.herbier for the Jv bindings
    map.js                the ~100-line MapLibre facade (architecture §8), imported by vendor.js
  map/
    positron.json         pinned OpenFreeMap style, plus the offline variant with a
    offline.json          pmtiles:// source and the Protomaps `white` flavour
  dist/                   NOT here: built into _build/default/web/dist by `dune build @web`
```

- Hand-written CSS concatenated to `dist/app.css`; class names follow the
  handoff vocabulary (`.chip`, `.card`, `.sheet`); `tokens.css` is generated.
- `webDir` points at `_build/default/web/dist`, so `npx cap sync` copies
  exactly what dune built; nothing generated is committed. The 4n
  illustration and app icons go under `web/img/`.

## 4. `android/` — Capacitor project and Kotlin

Generated once by `npx cap add android` and committed as Capacitor
recommends, with its own generated `.gitignore` for Gradle outputs. Our
edits, all under `android/app/src/main/`:

- `AndroidManifest.xml`: the `VIEW`/`BROWSABLE` intent-filters of
  architecture §7 and the `SEND text/plain` filter for the share target.
- `java/re/bruge/herbier/MainActivity.kt`: generated; only touched if a
  plugin needs manual registration.
- `java/re/bruge/herbier/`: any further Kotlin (a WorkManager constraint
  tweak) as one small Capacitor plugin class, bound from `app/bindings/`.
- `res/`: launcher icons, splash, `strings.xml`.

Keep native code to these files so a later move to a TWA loses nothing.

## 5. `supabase/`

```
supabase/
  config.toml             project settings (sign-ups off, auth providers)
  schemas/                declarative schema, one file per table + policies.sql,
                          triggers.sql (moddatetime, loc from lat/lon), rpc.sql (plants_near)
  migrations/             generated by `supabase db diff`, reviewed and committed
  tests/                  pgTAP: RLS (owner only, no anon), triggers, plants_near
  seed.sql                two plants for local `supabase start`
```

The backup/keep-alive cron (`supabase db dump` twice a week) and the dumps
it commits live in the **separate private repo `herbier-backups`**
(`.github/workflows/backup.yml`, `roles.sql`, `schema.sql`, `data.sql`).
Nothing in this repo reads them; this repo only documents the pointer.

## 6. `test/`

```
test/
  domain/       native, alcotest: merge rules, link classification, projection,
                places clustering, codec round-trips; runs in `dune test` on every CI job
  fixtures/     recorded API payloads (gbif_<key>.json, wikidata_<key>.json, tela_<nn>.json,
                inpn_<cd_nom>.json) used by projection and resolver tests
  js/           jsoo tests run under node (`(modes js)`): rb.ml against jsdom,
                Jv-level codecs; added only when the UI spike shows they pay off
```

Store, sync, photos and geo are thin over device-only plugins and have no
unit tests; the spikes (architecture §10) and manual runs cover them.

## 7. `scripts/` and CI

- `scripts/`: `dev.sh` (`dune build @web --watch` + `cap run android -l`),
  `subset-icons.sh` (Material Symbols subset from `icons.txt`),
  `pmtiles-extract.sh` (region extract for offline testing), `release.sh`
  (`dune build @web`, `cap sync`, `gradle assembleRelease`).
- `ci.yml`: `dune build`, `dune test`, `dune fmt --check`, `supabase test db`
  on a local stack. `android.yml`: debug APK on tag or manual run, uploaded
  as an artifact for sideloading.

## 8. Naming conventions

- `snake_case` files and directories; one module per file; no `types.ml`
  dumping ground, each entity is its own module.
- An `.mli` next to every library module, screens included (they export one
  `make`); `main.ml` and generated `version.ml` have none.
- Bindings are named after the JS package (`cap_sqlite`, `maplibre`) and
  expose the JS API shape, not our vocabulary. Screens are named after what
  they show, in English, handoff id in the first comment; French strings
  live in the screen, no i18n layer.
- SQL: plural tables, `snake_case` columns, `<timestamp>_<verb>_<object>.sql`.

## Decisions to make

1. **One dune library with subdirs vs one library per `app/` subdir.**
   Options: (a) single `herbier` library, `(include_subdirs qualified)`;
   (b) one library per subdir, `herbier_<dir>`, `domain/` also built
   natively; (c) (b) with domain as its own opam package. Recommend (b):
   dune enforces the dependency direction and domain tests run native.
2. **Package management.** Options: (a) opam switch + `herbier.opam.locked`;
   (b) `dune pkg lock` with `dune.lock/` committed; (c) opam locally, dune
   pkg in CI. Recommend (b): one tool, `dune build` alone works in CI.
3. **Capacitor project location and commit policy.** Options: (a)
   `android/` at root, committed (Capacitor default); (b) `capacitor/android/`
   with config alongside; (c) `android/` gitignored, regenerated plus a
   manifest patch script. Recommend (a): tooling assumes it, and the
   manifest diff is the whole native layer.
4. **Design tokens source.** Options: (a) `tokens.ml` is the source and a
   dune rule emits `tokens.css`; (b) `tokens.css` hand-written and
   `tokens.ml` duplicates the few values OCaml needs (map colours, circle
   fill); (c) CSS only, OCaml reads `getComputedStyle`. Recommend (a).
5. **CSS organisation.** Options: (a) four hand-written files concatenated
   to one `app.css`; (b) one file per screen under `css/screens/`; (c)
   styles emitted from OCaml. Recommend (a): the widget set is small and the
   handoff already groups things this way.
6. **JS-side dependencies.** Options: (a) esbuild bundle `vendor.js` from
   npm; (b) vendored minified files under `web/js/vendor/`, no bundler;
   (c) `window.Capacitor.Plugins` for plugins plus vendored libs. Recommend
   (a): plugins ship as ES modules and npm already exists for the Capacitor CLI.
7. **Where the jsoo output lands.** Options: (a) `_build/default/web/dist`
   via a dune alias, `webDir` pointing into `_build`; (b) `web/dist/`
   gitignored, filled by a shell script. Recommend (a): no copy step, no
   stale output.
8. **Supabase schema.** Options: (a) declarative `schemas/` + generated,
   reviewed migrations; (b) hand-written migrations only. Recommend (a) for
   a schema this small; hand-write only what `db diff` cannot express.
9. **jsoo tests.** Options: (a) none at first, native domain tests only;
   (b) `test/js/` with jsdom from day one for `rb.ml`. Recommend (a),
   revisit after the UI spike.
10. **Kotlin code location.** Options: (a) inline in `android/app/src/main`
    as a small Capacitor plugin class; (b) a separate local plugin package
    `capacitor-plugins/herbier-native/` linked from `package.json`.
    Recommend (a) unless a second native piece appears.
